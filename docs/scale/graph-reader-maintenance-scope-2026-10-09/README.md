# Reader maintenance namespace binding

The earlier experimental native loop shared one account-wide checkpoint and lease across graph authorities. It could resume an unrelated catalog cursor after configuration changed. Native maintenance now derives a stable SHA-256 scope from JSON encoding `[authority stream, subject prefix, object bucket]`. Opening the same adapters preserves the scope; changing any of those three namespace components changes it.

Checkpoint keys are `scan.graph-reader-expiry.<scope>`. The version-2 payload also contains the scope, so copying a checkpoint under another key fails validation. Lease identity uses `graph-reader-expiry-<scope>-reconciler` (one safe subject token). Public native loop construction requires a port that supplies the namespace scope. The generic deterministic loop continues to use the namespace-specific transport supplied by its caller.

The prior unscoped key and version-1 payload are not imported automatically. The new scoped key begins a fresh, idempotent reader pass when absent. Default runtime wiring, schema migration, object collection and public admission remain unchanged. New checkpoint isolation does not qualify an authority stream destroy/recreate operation; permanent authority history must still be preserved.

Controls check copied checkpoint rejection, stable/different scope identities and invalid/incomplete port scope. Native R1/R3 controls verify the second namespace sees no cursor, can acquire its lease while the first namespace holds a lease, and preserves the original cursor across adapter restart/lost acknowledgment. Existing renewal, CAS, malformed checkpoint and partial-progress controls are included. Eight existing maintenance traces are replayed against the current generic loop to check compatibility.

The initial attempt failed because a dot in the scoped checkpoint suffix was also used in the lease workflow identity. `initial-failure/` retains raw failure and actual exit. The corrected lease uses a hyphen; checkpoint keys retain their dot separator. Final command exits/input hashes and raw logs are retained in `results.json` and the group logs. The observed hashes cover the five selected implementation/test files, not an independent full compiler-input manifest. Full current/all-trace/extended, arbitrary interleavings, native fault/rollout and all original broader gates remain open.

Final race results: native scheduler/checkpoint groups R1/R3 plus deterministic controls pass in 4.679 seconds; scope identity control passes in 1.015 seconds; all eight existing maintenance traces pass shared corpus replay in 1.425 seconds. All three actual command exits are zero. No new seeded family or trace is added: inventory remains 154/824. The supervised full151 and corrected actor test processes are observed live and exclude these namespace changes.
