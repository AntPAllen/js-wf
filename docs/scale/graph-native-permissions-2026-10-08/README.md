# Native graph publisher and collector roles

The graph package now exposes `NativeSubjectAccess` for trusted adapters using default-deny NATS permissions. It reuses the authority allowlist and adds only one dedicated graph object namespace: native chunk/metadata publications, stream info and physical message reads. Consumer lifecycle and flow-control subjects are omitted because `NativePort.Get` does not create a consumer. Provisioning credentials are separate. Unlisted subjects must remain denied; do not combine this policy with publish/subscribe `>`.

The publisher has no purge API or stream lifecycle/retention API permission. The collector additionally receives only the named object bucket's purge API subject. NATS permissions cannot constrain its JSON purge filter; the collector must remain a trusted implementation. Both roles can write arbitrary metadata within their assigned namespaces and are not appropriate for untrusted workflow callers. Stream/bucket administrative ownership remains a separate control.

Native R1/R3 controls perform multi-chunk graph append/read, canonical payload reuse, preservation of live inherited receipts, and authenticated reconnection after server restart on its original store. Each fixture checks 37 exact permission denials, unchanged authority/object message counts and sequences after denied requests, and zero read consumers. The collector retires the graph, purges all physical chunks and retains permanent tombstones; a revoked publisher upload fails. Graph/direct formats continue to use distinct buckets/schemas.

The API prefix parameter supports explicit namespace construction, but these tests use `$JS.API` in the default native account. They do not qualify domains, account imports, deployed identities, administrator ownership, actual process/power loss, real partitions or full concurrency/scale campaigns. Canonical runtime migration, reader retention, partial compaction/import, production online GC and every original complete matrix/24h/million-drain/default-adoption/release gate remain required. The controls are local component regressions, not source/SDK/peer-media admitted native release qualification. Frozen final normal/race results are pending at this commit.

The failure precedes a graph operation assertion and does not qualify R3. Bucket admission now uses at most three read-only attempts, each bounded to two seconds in the caller’s original context, with stage-specific errors. It never retries a write or creates missing/unsafe storage. No claim of a confirmed server-side cause is made.

Object buckets allow metadata rollup for the adapter. Subject permissions do not constrain publication headers; together with arbitrary authority/object metadata writes, this requires trusted publishers as well as trusted collectors. Lack of purge API permission does not make an arbitrary publisher unable to damage its assigned namespace. These controls establish API subject restrictions for trusted implementation credentials, not an untrusted-principal storage security boundary.
