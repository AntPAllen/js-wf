# Resumable reader expiry scheduler

`RunGraphReaderExpiry` provides an explicit experimental JetStream-backed reader expiry loop; `RunReaderExpiryWithPort` is its shared deterministic boundary. The loop uses a dedicated system lease and versioned checkpoint in `WF_STATE` (`scan.graph-reader-expiry`). One configured isolated graph authority must be used consistently for that checkpoint/lease namespace.

Before a new catalog pass does any batch work, the loop persists its captured watermark and cursor atomically. A restart retains the same watermark. Renew precedes each batch and save. A confirmed partial batch may be checkpointed after uncertainty; the uncertain destination remains pending. Lost save acknowledgments or cursor conflicts release ownership and force a reload before further scanning. Expired leases do not authorize another save after failed renewal; root CAS fencing remains authoritative during in-flight work. A completed pass stores a zero checkpoint and waits for the configured cadence before beginning the next pass.

Five focused groups pass race (`focused-result.json`, tool actual exit 0, package 1.015 seconds): restart/lost save; lease loss before save; confirmed partial checkpoint; invalid configuration/checkpoint; production KV adapter boundary with committed lost create acknowledgment, CAS conflict, version/corrupt payload rejection. Tests model selected failures deterministically, not a new seeded-family qualification. The first restart fixture incorrectly advanced beyond the terminal protocol cursor; it was corrected to the real bounded end cursor before acceptance.

The loop never deletes objects and is not installed in the default runtime. Native cluster reader-loop integration, broader operation-level fault campaigns, scoped deployment configuration and rollout remain open. Existing live frozen race campaigns exclude this new scheduler. No full current-source, native fault/scale, soak, drain, migration, default-adoption or release acceptance is claimed.
