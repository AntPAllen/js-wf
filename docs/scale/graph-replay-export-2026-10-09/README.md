# Canonical graph replay export — 2026-10-09

The graph-configured `wf export-replay type id` now produces a self-contained offline bundle. `wf -handler-plugin FILE [-handler-symbol SYMBOL] replay type id` fetches that bundle through the same canonical path. Offline `wf -handler-plugin FILE -replay-bundle FILE replay` needs no server connection.

`worker.ReadGraphReplaySnapshot` opens one existing generation and pins its inputs/history. It validates the native invocation pointer against the canonical Start, copies the Start input, registers only runtime-declared payload references and reads each unique alias through a verified owned graph edge. Reused aliases must retain the same hash. It checks journal sequence/epoch boundaries, canonical consumed Signal index/token/sequence/name/hash/size against the captured queue, and the worker's existing parent-owned child result provenance. It does not begin or repair a generation, read compatibility state, resolve arbitrary user JSON strings or read legacy blobs. Errors and uncertain pin release clear the entire snapshot. Reader cleanup has a separate bounded context.

Rejected Signal drains retained in a journal-limit terminal record are checked against canonical queue metadata and the terminal record's owned body. The bundle's pending-Signal headers are synthesized from these verified canonical fields for the existing offline verifier; they are not native source headers. Source deletion cannot substitute another generation's payload.
