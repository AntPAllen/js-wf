# Bounded ordered journal decoding candidate

The explicit experimental checker overlaps journal decoding with chunk delivery using up to four workers, each processing bounded batches of at most64 records and1 MiB (or one oversized record). At most one additional accumulating batch is retained; the scanner may hold an incoming record while a byte batch is flushed. Decoder storage is reused. All reduction remains on the calling goroutine in stream order. Out-of-cohort filtering precedes decoding. Legacy JSON and versioned protobuf use the existing journal decoder. Captured source bounds, gap/resumption checks, state snapshot, compaction reconstruction, terminal values and semantic invariants are unchanged. Cancellation and early errors cancel and join every worker before return.

Existing public checker APIs retain serial decoding. The new full/cohort APIs select parallel decoding explicitly. The copied checkpoint runner has `--parallel-decode` and accepts `--archive` for a verified downloaded original archive; its fixed238560 cutoff and20-second attempt are unchanged. A separate independent reviewer requires the actual SDK environment and recorded result to agree on the selected mode, retains full source/copy/server/closure checks, and requires the full2630779-entry count. No production default or original24-hour verdict changes.

Controls cover deterministic out-of-order batch completion on513 seeded mixed JSON/protobuf records, filtering malformed later-cohort entries before decoding, first error before later decode/transport failure, visitor failure without revisiting, cancellation/worker joining, record/byte/oversized backpressure and partial-prefix reduction before a later scanner failure. Normal and race controls each passed count20. The initial race control failed because its byte-bound test omitted the scanner's incoming record; that failing log is preserved, the bound is explicit, and the corrected control passes. This is not a throughput qualification or NATS fault model.

The existing native invariant comparison now includes the new checker against the point-reader oracle for compaction, cohort exclusion, corruption, orphan journals, duplicate invocations and state mutations. Those native controls and the full copied-cohort candidate are pending at this source.
