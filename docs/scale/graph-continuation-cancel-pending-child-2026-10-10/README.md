# Cancel a continuation with an unresolved child

Frozen `57ee0b7187252a6a88b24ef655798cdfe3cf4b33` adds eight native race cases: R1/R3 domain × live/archive × successful/failed child. The parent carries an unresolved promise and state through two SDK checkpoints, then suspends. Cancellation is durably published, its dispatch wakeup removed and canonical signal repair required before execution. The parent must fail with the exact cancellation outcome without invoking another stage/effect or executing the child. Its acknowledged logical prefix and absolute indices remain unchanged; only one cancellation consumption and terminal are allowed.

The child is then executed independently, as required by v1. A successful child returns700,000 bytes, a failed child preserves its planned error. Late notification and duplicate parent/child deliveries cannot reactivate the parent or change its logical history. Archive cases collect after child completion and verify the child's terminal payload remains available; a fresh client must still see the original parent cancellation result. No legacy journal writes are permitted.

[Runner](run.py) records source inventories, retained race binary and actual exits from a clean detached checkout. [Launch identity](launch.json) binds the durable user systemd service. Raw artifacts live outside the repo; operational `state.json` stays uncommitted until terminal review. All runtime append/lease/recovery budgets are unchanged. New functional cases keep the pending-child fixture120-second watchdog and10-minute package watchdog.

Only worker test code differs from d504a33; production/model/trace inputs and the separate live full156 simulation campaign are unchanged. Launch is not acceptance. Running-effect cancellation, arbitrary parent/child fault interleavings, child cancellation propagation (v2), broad fault/scale/soak/retention, actual100000-entry limit, public admission and production collection remain separate open requirements.
