# Canonical Signal runtime in shared Tier1 simulation

`graph_canonical_signal_runtime` joins production client publication, canonical authority/owned input storage, bounded automatic Signal repair, worker consumption and replay, terminal projection and fixture collection through one seeded in-memory transport schedule. It uses the existing exact replay, failure trace, minimizer and pinned regression dispatcher. The source inventory grows from 144 to 145 seeded families. The graph CI matrix adds SignalRuntime in both normal and race modes.

Eighteen modes cover healthy delivery; reserved, source-committed, bound/no-enqueue and source-purged cuts; source reply loss; queue publication loss/unknown readback; enqueue loss; unknown catalog/lifecycle reads; dry discovery; 19-reservation batched recovery across reopened adapters; consumed-journal reply loss/unknown readback; and metadata-only repair during a prepared consumption append.

Every generated schedule is replayed exactly. It verifies correct Start/Signal input, suspension on the second Signal, adapter/worker reopen, contiguous consumed progress, terminal completion, exactly one effect, no legacy journal writes, matching terminal state, drained dispatch and zero modeled graph objects after explicit fixture retirement/collection. Every first Signal source is purged before worker intake. These are model invariants, not proof of native physical storage or OS crash behavior.

Development `first-1000.jsonl` passes all 1,000 complete seed bodies and all 18 modes (104.619 seconds package time). `initial.jsonl` preserves the rejected 100-seed configuration. `capture-1000.jsonl` preserves the absent capture-directory error; the corrected capture passes all 1,000 schedules and saves 18 unchanged exact traces, now in `sim/testdata/regressions/graph-signal-runtime-*.json`. Their source/hash/mode inventory is in `development/pin-inventory.json`. Development replay passes all 728 pins, including the original 710 unchanged. Frozen normal/race qualification is pending. Full final-source extended campaigns and all original native/scale/24h/million-drain/runtime-migration/default-adoption/release requirements remain open.
