# Native graph concurrency and SDK stream cache guard

The six-actor native workload prepares four append candidates concurrently, then releases four committers and two collectors using seeded permutations. It runs four rounds for seeds1/2 on R1/R3 (four fixtures, 64 candidate commits). Release permutations are seeded; native timing and winner counts are not deterministic. Shared Tier1 graph traces remain a separate qualification.

Each round accepts at most one original-head publication, checks monotonic heads/population, and independently walks raw child JSON to verify every acknowledged actor value and exact shared payload receipt. Abort errors are restricted to conflict/revocation or staged-object absence. Collector conflicts are safe bounded aborts; other errors fail. After actors join, a clean sweep must succeed. Final retirement must leave zero live objects and zero physical chunk subjects.

The initial R1/seed1 race run failed on the pinned nats.go v1.54.0 stream cache: concurrent native calls write `stream.info` in `Info` while other calls write/read the same pointer. The complete race report and exact test source are retained under `development-failure/`. This confirms a client SDK handle concurrency defect in the adapter's use of the shared handle; it is not a NATS server rollback or partition cause.

The adapter now guards each owned SDK stream handle. Info, cached info, GetMsg, GetLastMsgForSubject and Purge are protected per individual call. Waiting for that handle observes the original caller context. Whole protocol operations and metadata publications remain concurrent; original-head CAS and scoped grants still arbitrate at the actual server. The adapter does not modify the SDK dependency or enable runtime graph migration. A held-call control verifies canceled/deadline waiters never enter the SDK and the handle remains reusable.

The first guarded race workload passed all four fixtures, preserving committed values and reclaiming all attempts. Its earlier-source log remains a precursor; frozen final normal/race controls are pending at this commit. This is component regression with embedded native servers, not complete concurrent/partition/crash/power-loss/scale/history/deployment admission. The earlier direct blob adapter's SDK handle use is separate and still needs review. Reader retention, partial compaction/import, canonical runtime adoption, production onlineGC, all current-source simulation/native matrices/24h/million physical drain/default-adoption/release gates remain open.
