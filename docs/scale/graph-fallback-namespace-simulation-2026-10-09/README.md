# Seeded fallback namespace recovery

The `graph_fallback_namespace` workload invokes the production graph fallback timer scanner against two independent graph transports sharing invocation and timer source ports. It covers six modes (healthy, unknown root read, publish request/acknowledgment loss, and delete request/acknowledgment loss), both hint orders and batch budgets one/two: 24 declared combinations. Each body generates a trace and runs exact replay through `ReplayScheduler` and `Finish`, with full decision/transport equality checks.

The source boundary models immutable hints, request/acknowledgment loss, and message-ID deduplication within the short scenario. The production scanner decides ownership, current native source/token validity, journal timer declarations, publication and deletion. A fresh scanner is reconstructed on each batch/retry; the controller retains only confirmed cursor progress. Recovery is bounded to 16 attempts per store. Every selected fault must be consumed. Assertions require no foreign wakeup/deletion, one deduplicated wakeup per owner, both hints removed by their owners, unchanged canonical graphs/lifecycle bytes and object bytes, valid raw references and zero leaked reader pins.

## Evidence

`normal.log` and `race.log` contain actual completed-body markers for first=1, last=1000, completed=1000, requested=1000 and all 24 positive tuple counts. `results.json` records exact commands and actual child exits. The normal run completed in 19.614 seconds and race in 207.676 seconds. `observed-race-build-info.txt` was read from the live test executable and confirms actual race instrumentation; no retained full binary or complete compiled-input provenance claim is made.

Six new shared replay pins (one per fault mode) are listed with seeds/hashes in `pins.json`; `pins-normal.log` and `pins-race.log` exercise the shared corpus registry, not a private replay path. Normal pins pass in 0.104 seconds; race pins pass in 2.195 seconds. The 24 first-per-tuple development traces remain under `/home/exedev/js-wf-fallback-namespace-traces-confirmed-20261009`; only six are registered. They are representative successful schedules, not minimized failing traces.

The official AST-based seed inventory lists 156 families, all present in the compiled test listing; the full corpus contains 841 traces. The prior 835 tracked traces are unchanged. A `TestSeeded` name-prefix listing alone misses seeded tests with other names, so it is retained only as a diagnostic. `inventory.json` records the authoritative inventories. The focused `review.py` checks terminal markers, tuple totals, pin replay passes/hashes and five unchanged selected source/module hashes. It does not verify complete repository/binary provenance.

## Development evidence

`development-clock.log` and its retained failing trace preserve the first exact-replay failure: the new fixture used GraphStore's wall-clock default. The fixture now supplies virtual scheduler time, making reader/intent expiry bytes deterministic. `development-output-directory.log` preserves a failed optional trace-save attempt before its output directory existed; it completed zero tracked seed bodies and is not acceptance. The initial controller normal/race and pin runs also passed, but the review found that deletion-ack loss could end recovery based on raw model state. The final controller requires a successful replacement scan before declaring that hint recovered, including observing its absence after a lost delete acknowledgment. Those earlier logs and six pins are preserved with `initial-controller-` names. Final logs/pins were regenerated and requalified after the correction. No production behavior, fault domain or deadline was relaxed.

## Remaining scope

This is sequential scanner replacement and source-fault simulation. It does not model arbitrary operation interleaving, native replication, dedup-window expiry, process/VM death, clock-skew admission, or namespace-aware worker dispatch. Pending local reservations remain covered by the earlier directed fail-closed control rather than a mode in this family. It qualifies neither a complete multiple-store deployment nor production collection. Full current 156-family/all-841-pin normal/race/extended acceptance and every original runtime/lifecycle/purge/retention/native fault/scale/soak/drain/migration/release requirement remain open. The live frozen full151 and expiry race campaigns and queued frozen full155 normal exclude this later work.
