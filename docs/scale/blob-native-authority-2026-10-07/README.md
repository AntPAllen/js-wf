# Experimental native blob authority

`NativeAuthority` implements the durable metadata/reference portion of the experimental protocol. It opens an explicitly provisioned stream, never silently creates a missing one. Latest records carry logical revision/head/generation high-water values; CAS publishes against the actual last subject sequence. Interleaved subjects therefore cannot confuse global stream sequences with logical destination heads.

The authority requires file storage, Limits retention, exactly one retained record per subject, no age/global message/byte limits, no per-message TTL, no direct reads, no rollups/transforms/mirror/sources/republish, acknowledgments and deny-purge/deny-delete. Configuration is checked at every operation. Reads use the normal leader API rather than direct follower reads. Generation selection is immutable; retired destinations and closed generations retain their authority. Opening uses at most three fresh two-second read-only metadata attempts within the caller's deadline; missing or unsafe authorities are not retried or recreated.

Development R1 and R3 race tests pass actual native CAS, interleaved logical heads, native purge/delete denial, immutable object selection, generation advance, mixed subject census, same-store node0 restart and rejection of old initial CAS. A controlled wire fixture holds a complete333-byte publication before upstream forwarding, advances the actual destination fence, then releases every original byte; native publication rejects the stale server CAS. The exact subject selector is also tested against sibling/metadata packets and existing API selectors.

Nine native unsafe-configuration cases and a post-open retention mutation are rejected. These are authority component tests. No ObjectStore calls or runtime workflow streams are integrated; this does not qualify online GC or arbitrary partitions/lost replies. Administrator stream deletion/recreation or concurrent relaxation of configuration must be forbidden by ownership/permissions; a read-time config check cannot atomically prevent a privileged mutation. Full workflow reference history and migration remain required.

Preliminary census/startup/reopen failures are retained with their precise scope. The census assumption is confirmed client-side: `NumSubjects` counts the whole mixed stream even when the subject map is filtered. R3 creation needs complete metadata peer admission; observing a leader alone produced a no-suitable-peers error. Exact server-side causes of earlier startup/reopen timeouts remain unconfirmed. Admission checks and opening remain inside the original20s per-case parent; no deadline extension is used. Original development runs without retained fixture mode performed ordinary Go temporary cleanup and are not presented as archived native qualifications.

Final committed-source native evidence is recorded separately after qualification. Original123/new124 graph gates, native matrices, million physical drain and actual24h remain independent.
