# Shared offline child selection validation

The previous SDK replay accepts an ordinary canonical signal consumed before
its child request as the child's result, both for Call and AwaitPromise. The
requests/completions in the reproduction are generated by the SDK; the signal
has no graph_child binding. The [actual old diagnostic](old-diagnostic.log)
fails both required rejection cases with result42/no error.

Graph child annotation validation now lives in the shared wf replay layer. The
CLI still validates before plugin loading, using the same implementation.
Replay captures verified graph child signals and installs a selected-result
validator on its initial context and every restored continuation context. Exact
signal sequence/name/payload must match a verified binding. Ordinary signals
remain usable by ordinary AwaitSignal; unannotated legacy child histories keep
their existing path. Graph checkpoint metadata also identifies graph histories
before any signal has been consumed.

Six synchronous/asynchronous legacy/unbound/bound cases and four checkpoint
legacy/ordinary/child cases pass in development. Disabling only validator
installation requires three failures: Call, AwaitPromise and selection from a
real SDK checkpoint's pending-signal frame. [Negative control](disabled-selector.log)
and [actual receipt](disabled-selector-receipt.json) are preserved. Shared SDK
and complete corpus/native-export/CLI qualification follow from frozen source;
this development result is not full qualification. Full offline provenance,
fault/buffered-signal/import/rollout, retention/admission, actual100,000-entry
boundary, public/default admission, production collection and all broader
original requirements remain open.
