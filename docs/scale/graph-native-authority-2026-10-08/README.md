# Experimental native graph metadata authority

`internal/graphpublication/NativeAuthority` implements the metadata subset of the graph Port on an explicitly provisioned dedicated JetStream stream and subject prefix. This is component work toward graph adoption; it supplies no native graph object adapter and does not enable production collection.

## Durable contract

The new envelope is `js-wf-graph-authority-v1`. Decode rejects foreign/legacy schemas, unknown fields, duplicate fields, case aliases, trailing bytes, noncanonical encodings, identity changes and values above 36 KiB. Graph roots and scoped grants are validated before writes. Per-subject retained records preserve logical heads, grant revisions and generations, including absence witnesses and closed scopes. Heads/revisions increment once on acknowledged mutation; physical global stream sequences are independent. Closed scopes only reopen at the next generation; a selected immutable object cannot change within a generation.

Reads use the existing same-subject `ReadWithWitness` decision with at most 16 conflict retries in the original context. A tentative GET or absence must be conditionally reaffirmed by an acknowledged native write. A stale snapshot loses that condition. A lost witness reply fails closed even if the write committed. CAS uses a tentative GET sequence only to condition its original-head write, never to report a successful read. Uncertain CAS returns no proposed root/grant and performs no automatic retry.

Opening never provisions missing storage. Every operation checks permanent file storage, one retained value per subject, no expiry/size/message eviction, forbidden purge/delete, acknowledgments, and absence of direct-read/TTL/rollup/mirror/source/transform/republish behavior. Administration must not delete or recreate authority streams; this contract does not defend against privileged administrators. Subject-prefix ownership and graph object bucket isolation still require deployment admission.

## Tests and limits

Focused R1/R3 tests exercise root graph metadata, absence witnesses, interleaved physical sequences, stale heads, closed/reopened generations, independent returned grant copies, native server shutdown/restart on its original store, purge/delete rejection, stale root/grant GET and absence controls, bounded conflict exhaustion, committed-but-lost witness and mutation replies, and mutual graph/direct-schema rejection without rewriting bytes. Native malformed-wire controls reject reads/CAS without repair; unknown census subjects stop enumeration. A separate 22-policy mutation group rejects unsafe configuration before reads or writes.

Root node bytes in the persistence fixture are generated by the memory graph protocol: they are not native object writes or a native end-to-end graph collection proof. Wrapper controls execute actual native conditional writes but deliberately alter GET/reply delivery. They do not establish real network partition, permissions, process/power loss or linearizability qualification.

The first development persistence run failed on both replicas because the fixture reopened through the old pinned client after `RestartNode` replaced and closed that connection. Its exact test source and failure log are retained in `development-failure/`. The fixture now opens JetStream on the replacement client. Focused final controls pass; complete package normal/race regression is pending at this source commit.

Native object uploads/ambiguous attempt cleanup and bucket isolation, graph-aware native collection, reader retention pins, partial compaction, legacy import/schema migration, complete canonical runtime adoption, original full matrices/24h/million physical drain/default dependency adoption/release gates remain open.

## Destination encoding correction

Review after the first full normal run found that Go JSON replaces invalid UTF-8 in strings. Accepting an invalid destination could therefore publish a durable envelope whose identity no longer matched its hashed subject. Root identities, protocol append destinations and grant destinations now reject invalid UTF-8 before any write, while valid Unicode destinations are preserved. A native control verifies no authority sequence change for rejected identities or grants. The first full normal run (7.999s) at `a36e2c4` is retained as precursor evidence; final source qualification follows this correction.
